# NYPD — Killer Features & Scope Notes

> Статус: v0.1. Сюда — крупные системные фичи, которые могут стать маркетинговыми козырями, плюс честные scope-рекомендации по срокам/риску.

## Редактор уровней + UGC (предложено пользователем)
**Идея**: редактор в духе Mario Maker — игроки строят уровни, выкладывают в общий доступ, соревнуются на них.

**Почему это сильно**: лидерборды + replay-система + короткие линейные уровни с шорткатами (уже зафиксированы в gameplay_design.md) — весь фундамент для UGC уже закладывается естественным путём. Community-контент превращает игру в живой продукт на годы (референсы: Geometry Dash, Trackmania, N++, LBP). Сильный аргумент для инвесторского питча — движок генерации контента почти бесплатно после релиза.

**Риски/scope**: полноценный редактор — это по сложности отдельный продукт (UI редактора, тест-плей режим, сохранение/загрузка, сервер хостинга, браузер/поиск уровней, модерация неприемлемого контента). Не просто геймдизайн-фича, а инфраструктура + операционные расходы post-launch.

**Рекомендация**: зафиксировать как **post-launch контент-дроп**, не часть v1.0. Проверенный индюшный паттерн (Dead Cells, Risk of Rain 2 — крупные обновления после релиза для второй волны интереса/продаж). Для инвесторов это даже выигрышнее: roadmap роста после релиза, а не весь риск в одной дате.

**Техническая зависимость**: усиливает приоритет детерминированной симуляции (фикстаймстеп + запись инпутов вместо позиций) — без неё ни replay, ни безопасный шеринг/проверка community-уровней не реализуются нормально. Закладывать в архитектуру с самого начала, даже если сам редактор — это v2.

## Кастомизация персонажа (предложено пользователем)
**Идея**: очки характеристик/перков на распределение (быстрый-но-слабый ниндзя и т.д.). Кастомные персонажи не участвуют в общем лидерборде — только для фана/тестов.

**Разделение leaderboard vs custom**: подтверждено и это правильное решение — иначе соревновательность ломается мгновенно.

**Риск**: левел-дизайн (особенно шорткаты, точные гэпы по дистанции дэша) спроектирован вокруг конкретных чисел движения. Свободные слайдеры статов могут сломать решаемость уровня в фан-режиме (гэп не пролетается / шорткат становится тривиальным).

**Рекомендация**: discrete-перки/модули (аналог Charms в Hollow Knight), меняющие стиль игры в заданных тобой рамках, а не свободные числовые слайдеры без границ. Даёт ощущение персонализации без риска сломать левел-дизайн.

**Статус**: вторичная фича, не "киллер" в смысле маркетингового дифференциатора — скорее приятный слой реиграбельности/фана.

## Решения
- **Редактор уровней — post-launch контент-дроп**, не часть v1.0. Зафиксировано.

## Найм курьеров/поваров (Mother Base / Garrison-style)
**Идея**: по ходу прохождения в додзё можно нанимать новых курьеров/поваров, отправлять их на заказы (аналог MGS Mother Base, гарнизона Дренора в WoW, систем в Assassin's Creed), затем смотреть replay их прохождения уровня (смешные провалы или впечатляющие успехи).

**Сильная сторона**: даёт метагейму собственный engagement-луп, не зависящий от активной игровой сессии — классический retention-хук ("отправил юнита, вернулся позже за результатом"). Завязка на replay-систему добавляет персонажу/юмору игры, вписывается в комедийный тон (Майки и т.д.) — потенциально шерабельный контент (смешные провалы бота).

**Технический совет**: не симулировать настоящего AI-агента, проходящего уровень твоим сложным мувсетом — это дорогая и рискованная разработка (бот может выглядеть откровенно сломанным, а не "забавно неуклюжим"). Вместо этого: бросок кубика (успех/провал на основе статов нанятого vs сложности уровня) → проигрывание срежиссированной vignette по результату броска. Можно ремиксовать существующую ghost-replay систему (взять реальный человеческий забег, вставить "ошибку" в нужном месте под результат броска) — даёт тот же эффект в разы дешевле.

**Scope-флаг**: ещё одна крупная система поверх уже накопленного списка (редактор, кастомизация, экономика, хаб-минигеймы). **Решено: post-launch**, как и редактор уровней — не блокирует core-цикл игры.
