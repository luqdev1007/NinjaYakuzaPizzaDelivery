# NYPD — Ninja Yakuza Pizza Delivery

## Что это
2D action-platformer на Unity. Ядро — скоростное и **стильное** прохождение
коротких уровней на время (спидран + DMC-подобная стиль-система). Референсы:
Katana Zero, Ghostrunner, DMC, Hollow Knight. Steam (PC приоритет, PS — порт).
Design pillar: **скорость = урон** — движение и бой одна система, не параллельные.
Solo-разработка. Цель — релиз, дальше портфолио под инвестиции/команду для 2-й части.

явно флагай расхождение, не подгоняй код под доку молча.

## Архитектура (кратко; детали в tech_architecture.md)
- **DI-контейнер** самописный: иерархический (project-scope → gameplay
  scene-scope), singleton lifetime, lazy по умолчанию, `.NonLazy()` для eager.
  Массовое создание сущностей — через `*Factory`, НЕ через DI lifetime.
- **ECS-lite**: `Entity` = контейнер `IEntityComponent` + собственные списки
  систем (`IInitializableSystem`/`IUpdatableSystem`/`IDisposable`). Не DOTS —
  per-instance композиция поведения.
- **Реактивка**: `ReactiveVariable<T>`, `ReactiveEvent<T>`, `ReactiveEvent`,
  `ICompositeCondition`. Equality-check перед инвоком, buffered add/remove подписок.
- **UI на MVP**: `IView`/`IPresenter`, попапы через Presenter+Service+DOTween.
  Референс-образец: `CurrencyPresenter`/`WalletPresenter`.
- DOTween — анимации, Cinemachine — камеры, самописный state machine — флоу.

## Конвенции кода
- **Всегда полный переписанный файл**, не диффы и не сниппеты.
- **Никаких однострочных `if`**: условие и действие на разных строках, даже для
  одного оператора.
- Пиши в стиле существующей архитектуры (DI/реактивка/MVP). Не тащи
  vanilla-MonoBehaviour подход без явного запроса.
- `[FormerlySerializedAs]` при переименовании сериализованных полей.

## Правила работы
1. **Не угадывай архитектуру.** Устройство системы неясно из доков — читай код;
   всё равно неясно — спрашивай, не изобретай.
2. **Проверяй существующую инфраструктуру перед новой.** Прежде чем предлагать
   новый сервис/трекер — убедись, что параллельного уже нет.
3. **Single-writer для реактивных флагов.** Один флаг — один писатель. Разные
   семантические состояния — разные компоненты (иначе тихий orphaning).
4. `StateMachine.Dispose()` обязан звать `Exit()` — иначе глобальные синглтоны
   (`IInputService.IsEnabled` и т.п.) остаются грязными при жёстком teardown сцены.
5. **Тайтовый скоуп.** Не расширяй поверхность задачи. Файлы вне текущего скоупа
   не трогай без подтверждения.

## Известные технические риски (high)
- Leftover `NotImplementedException`-заглушки в нескольких местах.
- `EntityAPIGenerator` на `[InitializeOnLoadMethod]` — риск нестабильных
  домен-релоадов (цель: только ручной `[MenuItem]`).
